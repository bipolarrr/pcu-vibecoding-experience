# 전공체험 박람회용 모듈형 테트리스

## 프로젝트 개요

자연어 요청이 실제 게임 기능으로 반영되는 과정을 체험하기 위한 웹 기반 테트리스이다. 체험자는 코드를 직접 작성하지 않고 원하는 기능과 디자인을 설명한다. Codex는 요청 범위를 해석하여 게임에 반영하고, 변경 결과와 조작법을 안내한다.

이 저장소는 기능이 없는 흑백 기준판에서 시작한다. 기준판과 기능이 추가된 결과의 차이를 명확히 제시하여, 한 번의 요청이 하나의 사용자 경험으로 연결되는 과정을 확인할 수 있도록 구성하였다.

## 체험 원칙

- 한 요청은 사용자가 하나의 기능으로 인식하는 범위에 대응한다.
- 요청하지 않은 기능은 임의로 추가하지 않는다.
- 내부 선행 기능은 함께 정합하되 별도 성과로 설명하지 않는다.
- 구체적인 스타일 요청은 해당 디자인으로 즉시 반영한다.
- 방향이 정해지지 않은 디자인 요청에는 스타일 갤러리를 먼저 제시한다.
- 완성 요청에는 표준 기능을 적용하고, 고급 규칙은 명시적으로 요청된 경우에만 포함한다.

예를 들어 “블록이 어디에 떨어질지 보여 줘”라는 요청은 착지 위치 표시만 추가한다. 점수 요청에 최고 점수나 점수 효과를 함께 포함하지 않는다. 이러한 범위 통제는 자연어 요청과 구현 결과의 대응 관계를 명확하게 유지하기 위한 기준이다.

## 기준 상태

초기 화면은 흑백 색상과 Comic Sans 글꼴을 적용한 테트리스 기준판이다. 점수, 다음 블록, 블록 보관, 즉시 낙하, 일시정지와 같은 부가 기능은 활성화되어 있지 않다.

기본 조작은 다음과 같다.

| 입력 | 동작 |
|---|---|
| `←` · `→` | 블록 좌우 이동 |
| `↓` | 한 칸 낙하 |
| `↑` | 시계 방향 회전 |
| `Enter` | 게임 종료 후 재시작 |

추가 기능의 조작법은 게임 화면에 표시한다. 완료 안내에서는 요청한 기능이 새 입력을 추가하거나 기존 입력을 바꾼 경우에만 해당 조작법을 설명한다.

## 실행 환경

게임 자체는 빌드 과정이 없는 정적 웹 애플리케이션이다. 시연 운영 페이지가 로컬에서 게임 서버와 Codex 실행을 제어하므로 VS Code 서버 확장은 필요하지 않다. 행사 장비에는 Git, Node.js, npm과 Codex가 설치되어 있어야 한다.

Windows 시연 장비는 Scoop으로 설치하여 `PATH`에 등록된 Codex CLI를 기준으로 한다. 새 명령 프롬프트에서 아래 두 명령이 별도 경로 지정 없이 실행되어야 한다.

```text
node --version
codex --version
```

시연 스크립트는 Scoop의 사용자별 설치 경로를 직접 사용하지 않고 `PATH`에서 `node`와 `codex`를 찾는다.

Windows에서는 저장소 디렉터리에서 다음 명령으로 시연 운영 페이지를 연다.

```text
npm run showcase:control
```

기본 브라우저의 `http://127.0.0.1:5174`에서 **시연 처음부터 시작**을 누르면 운영 페이지에 준비 단계가 표시된다. 기준판 복원과 Codex 사전 준비를 마친 뒤 게임 서버와 Codex를 시작하고, 마지막에 변경 감시 전용 터미널(Live Code)과 게임 화면을 연다. 감시 터미널에는 Codex가 변경하는 `src/` 코드가 실시간 diff와 타이핑 효과로 표시된다. 필수 환경 점검에서는 Node.js, Codex CLI와 로그인 상태, 인터넷 연결을 실제로 확인한다. 개별 작업 버튼으로 상태 확인, 환경 점검, 게임 서버와 Codex 명령을 따로 실행할 수도 있다.

터미널에서 직접 게임 서버나 Codex만 실행하려면 다음 명령을 사용한다.

```text
npm run dev
npm run showcase:start
```

브라우저의 ES module 정책으로 인해 `index.html`을 파일 경로로 직접 열지 않는다. 자동 검증에는 Node.js를 사용하며, 런타임 의존성 설치는 필요하지 않다.

## 체험 진행

### 자연어 요청

체험자는 원하는 변화를 일상적인 표현으로 요청한다.

- “스페이스바로 바로 떨어뜨리고 싶어요.”
- “다음 블록을 미리 보여 주세요.”
- “게임을 네온 오락실처럼 화려하게 바꿔 주세요.”
- “무엇을 더 추가하면 좋을까요?”

Codex는 현재 활성 상태를 확인한 뒤 요청과 직접 대응하는 기능만 반영한다. 완성 요청에는 아직 활성화되지 않은 표준 기능을 짧게 설명하고 같은 작업에서 적용한다.

### 디자인 선택

전체 디자인은 네온 아케이드, 클래식 픽셀, 미니멀 현대형의 세 프리셋을 제공한다. 각 프리셋은 색상, 글꼴, HUD 배치와 간격, 보드 표현, 배경, UI 장식의 여섯 축을 일관된 방향으로 구성한다. 게임 전체의 화면 정렬은 프리셋과 독립적으로 유지되며, 왼쪽·가운데·오른쪽과 위쪽·가운데·아래쪽 요청에 따라 각 축만 변경한다.

`style-gallery.html`에서 세 프리셋을 비교할 수 있다. 화면 전체를 “네온 느낌으로 바꿔줘”처럼 분위기로 요청하면 전체 디자인을 적용한다. 색상이나 글꼴을 지정한 요청은 분위기 표현이 함께 있어도 지정한 요소만 바꾸고 나머지 상태는 유지한다. “글씨가 못생겼어” 또는 “색이 별로야”처럼 방향 없는 불만에는 원하는 글씨나 색 조합을 먼저 묻는다. 색 조합을 직접 지정하면 전달받은 색만 반영하고, 화면 전체의 분위기를 답하면 그 방향의 디자인을 적용한다.

### 기능 범위

표준 기능은 즉시 낙하, 착지 위치 표시, 다음 블록, 블록 보관, 점수, 레벨, 일시정지, 시청각 효과와 편의 기능으로 구성된다. SRS, T-spin, 콤보, back-to-back은 선택형 고급 규칙이며 명시적인 요청이 있을 때만 적용한다.

기능별 요청 의도와 선행 관계는 [기능 목록](.showcase/CATALOG.md)에 명시되어 있다.

## 다국어 지원

한국어, 영어, 일본어, 베트남어, 중국어 간체를 지원한다. 표시 언어는 URL의 `lang` 값, 저장된 설정, 브라우저 언어, 한국어 기본값 순서로 결정한다.

다음과 같이 URL에 언어 코드를 지정할 수 있다.

```text
index.html?lang=ko
index.html?lang=en
index.html?lang=ja
index.html?lang=vi
index.html?lang=zh
```

새 UI 문구는 `src/i18n/`의 모든 언어 사전에 같은 번역 키로 등록한다. 화면 문구를 HTML이나 기능 코드에 직접 기재하지 않는다.

## 시연 환경 관리

저장소 루트에서 다음 명령을 사용한다. Linux와 Windows에서 동일하다.

```text
npm run showcase:status
npm run showcase:reset
npm run showcase:baseline
npm run showcase:control
npm run showcase:start
```

`showcase:status`는 현재 상태와 로컬 `showcase` 브랜치의 최신 커밋이 일치하는지 확인한다. 올바른 브랜치의 미커밋 변경은 초기화 대상이 아니라 현재 시연에서 누적 중인 변경으로 표시한다. 게임 서버로 연 브라우저 화면은 프로젝트 파일이 변경되면 자동으로 새로고침된다. `showcase:start`는 현재 터미널을 점유하지 않고 별도 명령 창을 즉시 열며, 새 창에서 누적 변경을 그대로 유지한 시연 전용 Codex 세션을 시작한다. `showcase:reset`은 운영자나 사용자가 명시적으로 실행할 때만 체험 변경을 Git branch와 stash에 보관한 뒤 기준 커밋을 복원한다. 이 명령들은 원격 저장소에 접근하지 않으므로 pull 이후에는 네트워크 없이 사용할 수 있다.

같은 프로젝트의 운영 페이지가 열린 상태에서 `npm run showcase:control`을 다시 실행하면 기존 게임 서버, 변경 감시 창, Codex 창과 운영 서버를 종료한다. 이어서 기준판 복원부터 전체 시연 시작 절차를 자동으로 다시 수행한다. 다른 프로젝트나 프로그램이 운영 포트를 사용 중인 경우에는 해당 프로세스를 종료하지 않는다.

새 Codex 창은 운영 페이지가 물려받은 `TERM=dumb` 값을 제거한 뒤 실행한다. 새 콘솔이 자신의 터미널 기능을 감지하므로 일반 Codex 대화형 화면과 색상을 유지한다.

`showcase:baseline`은 현재 커밋을 로컬 `showcase` 브랜치의 기준으로 확정하는 운영자 전용 명령이다. 작업 트리가 깨끗하고 시연 필수 환경 점검이 통과할 때만 실행한다.

행사 장비에서는 시연 전에 한 번만 아래 순서로 원격 기준판을 동기화한다.

```text
npm run showcase:reset
git pull --ff-only origin showcase
npm run showcase:status
```

## 시연 환경 점검

행사 시작 전 시연에 꼭 필요한 Node.js, Codex CLI와 로그인 상태, 인터넷 연결을 점검한다.

```bash
npm test
```

이 명령은 게임 엔진이나 미리 작성된 기능의 구현 내용을 다시 검사하지 않는다. 시연 세션의 에이전트는 기능 변경 후 문법 검사가 통과하면 정상 적용된 것으로 간주하며, 브라우저나 게임 화면을 열어 확인하거나 모니터링하지 않는다.

## 저장소 구성

| 경로 | 역할 |
|---|---|
| `index.html` | 게임 진입 화면 |
| `style-gallery.html` | 디자인 프리셋 비교 화면 |
| `src/core/` | 게임 엔진과 공통 서비스 |
| `src/features/` | 현재 활성 기능 |
| `src/i18n/` | 지원 언어별 번역 사전 |
| `.showcase/CATALOG.md` | 기능 범위와 선행 관계 |
| `.showcase/packs/` | 적용 가능한 기능 모듈 |
| `scripts/showcase-readiness.js` | Node.js·Codex·인터넷 연결 점검 |

핵심 엔진은 기능과 분리되어 있다. 각 기능은 자신의 UI, 스타일, event listener와 정리 절차를 소유하며, 기능 간 연동에는 공통 event 또는 capability를 사용한다. 이 구조는 기능을 추가하거나 제거한 뒤에도 나머지 게임 상태가 유지되도록 한다.

## 운영 기준

- 활성 기능과 요청 기능의 중복 여부를 먼저 확인한다.
- 새 요청은 현재 활성 기능에 누적하고, 명시적인 초기화 전에는 기존 기능을 일괄 제거하지 않는다.
- 선행 기능을 먼저 반영하고 충돌하거나 대체되는 기능은 제거한다.
- 활성 기능은 의존 순서에 따라 등록하며 조작 안내는 마지막에 등록한다.
- 기능 적용을 위해 `src/core/`를 변경하지 않는다. 기존 공개 계약으로 구현할 수 없는 요청만 구조 변경 대상으로 분류한다.
- 기능 제거 후 DOM, CSS, event listener와 timer가 잔존하지 않는지 확인한다.
- 체험자에게는 구현 결과를 안내한다. 요청 기능으로 새 입력이 생기거나 기존 입력이 변경된 경우에만 해당 조작법을 함께 안내한다.
