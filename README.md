# 전공체험 박람회용 모듈형 테트리스

## 프로젝트 개요

자연어 요청이 실제 게임 기능으로 반영되는 과정을 체험하기 위한 웹 기반 테트리스이다. 체험자는 코드를 직접 작성하지 않고 원하는 기능과 디자인을 설명한다. Codex는 요청 범위를 해석하여 게임에 반영하고, 변경 결과와 조작법을 안내한다.

이 저장소는 기능이 없는 흑백 기준판에서 시작한다. 기준판과 기능이 추가된 결과의 차이를 명확히 제시하여, 한 번의 요청이 하나의 사용자 경험으로 연결되는 과정을 확인할 수 있도록 구성하였다.

## 체험 원칙

- 한 요청은 사용자가 하나의 기능으로 인식하는 범위에 대응한다.
- 요청하지 않은 기능은 임의로 추가하지 않는다.
- 내부 선행 기능은 함께 정합하되 별도 성과로 설명하지 않는다.
- 구체적인 스타일 요청은 해당 디자인으로 즉시 반영한다.
- 방향이 정해지지 않은 디자인 요청에는 스타일 갤러리를 먼저 제시한다.
- 완성 요청에는 표준 기능을 적용하고, 고급 규칙은 명시적으로 요청된 경우에만 포함한다.

예를 들어 “블록이 어디에 떨어질지 보여 줘”라는 요청은 착지 위치 표시만 추가한다. 점수 요청에 최고 점수나 점수 효과를 함께 포함하지 않는다. 이러한 범위 통제는 자연어 요청과 구현 결과의 대응 관계를 명확하게 유지하기 위한 기준이다.

## 기준 상태

초기 화면은 흑백 색상과 Comic Sans 글꼴을 적용한 테트리스 기준판이다. 점수, 다음 블록, 블록 보관, 즉시 낙하, 일시정지와 같은 부가 기능은 활성화되어 있지 않다.

기본 조작은 다음과 같다.

| 입력 | 동작 |
|---|---|
| `←` · `→` | 블록 좌우 이동 |
| `↓` | 한 칸 낙하 |
| `↑` | 시계 방향 회전 |
| `Enter` | 게임 종료 후 재시작 |

추가 기능의 조작법은 해당 기능이 활성화된 뒤 화면과 완료 안내에 함께 표시한다.

## 실행 환경

게임은 별도 API 서버와 빌드 과정이 없는 정적 웹 애플리케이션이다. 실행에는 VS Code의 Five Server 확장을 사용한다.

1. VS Code에서 저장소 디렉터리를 연다.
2. `index.html`을 Five Server로 실행한다.
3. 브라우저에 표시된 게임을 조작한다.

브라우저의 ES module 정책으로 인해 `index.html`을 파일 경로로 직접 열지 않는다. 자동 검증에는 Node.js를 사용하며, 런타임 의존성 설치는 필요하지 않다.

## 체험 진행

### 자연어 요청

체험자는 원하는 변화를 일상적인 표현으로 요청한다.

- “스페이스바로 바로 떨어뜨리고 싶어요.”
- “다음 블록을 미리 보여 주세요.”
- “게임을 네온 오락실처럼 화려하게 바꿔 주세요.”
- “무엇을 더 추가하면 좋을까요?”

Codex는 현재 활성 상태를 확인한 뒤 요청과 직접 대응하는 기능만 반영한다. 완성 요청에는 아직 활성화되지 않은 표준 기능을 짧게 설명하고 같은 작업에서 적용한다.

### 디자인 선택

전체 디자인은 네온 아케이드, 클래식 픽셀, 미니멀 현대형의 세 프리셋을 제공한다. 각 프리셋은 색상, 글꼴, 배치, 보드 표현, 배경, UI 장식의 여섯 축을 일관된 방향으로 구성한다.

`style-gallery.html`에서 세 프리셋을 비교할 수 있다. 색상이나 글꼴처럼 하나의 디자인 요소만 요청한 경우에는 해당 요소만 교체하고 나머지 상태는 유지한다.

### 기능 범위

표준 기능은 즉시 낙하, 착지 위치 표시, 다음 블록, 블록 보관, 점수, 레벨, 일시정지, 시청각 효과와 편의 기능으로 구성된다. SRS, T-spin, 콤보, back-to-back은 선택형 고급 규칙이며 명시적인 요청이 있을 때만 적용한다.

기능별 요청 의도와 선행 관계는 [기능 목록](.showcase/CATALOG.md)에 명시되어 있다.

## 다국어 지원

한국어, 영어, 일본어, 베트남어, 중국어 간체를 지원한다. 표시 언어는 URL의 `lang` 값, 저장된 설정, 브라우저 언어, 한국어 기본값 순서로 결정한다.

다음과 같이 URL에 언어 코드를 지정할 수 있다.

```text
index.html?lang=ko
index.html?lang=en
index.html?lang=ja
index.html?lang=vi
index.html?lang=zh
```

새 UI 문구는 `src/i18n/`의 모든 언어 사전에 같은 번역 키로 등록한다. 화면 문구를 HTML이나 기능 코드에 직접 기재하지 않는다.

## 품질 검증

모든 변경 후 전체 테스트를 실행한다.

```bash
npm test
```

테스트는 게임 엔진, 기능 설치와 정리, 기능 간 계약, 다국어 사전 정합, 기능 목록의 의존 관계를 검증한다. 자동 테스트 통과 후 Five Server에서 게임을 실행하여 다음 항목을 확인한다.

- 브라우저 console 오류 부재
- 요청 기능의 실제 동작
- 기존 조작과 기능의 유지
- 한국어·영어·일본어·베트남어·중국어 간체 표시
- 좁은 화면에서의 보드 및 UI 배치

## 저장소 구성

| 경로 | 역할 |
|---|---|
| `index.html` | 게임 진입 화면 |
| `style-gallery.html` | 디자인 프리셋 비교 화면 |
| `src/core/` | 게임 엔진과 공통 서비스 |
| `src/features/` | 현재 활성 기능 |
| `src/i18n/` | 지원 언어별 번역 사전 |
| `.showcase/CATALOG.md` | 기능 범위와 선행 관계 |
| `.showcase/packs/` | 적용 가능한 기능 모듈 |
| `tests/` | 자동 및 브라우저 검증 자료 |

핵심 엔진은 기능과 분리되어 있다. 각 기능은 자신의 UI, 스타일, event listener와 정리 절차를 소유하며, 기능 간 연동에는 공통 event 또는 capability를 사용한다. 이 구조는 기능을 추가하거나 제거한 뒤에도 나머지 게임 상태가 유지되도록 한다.

## 운영 기준

- 활성 기능과 요청 기능의 중복 여부를 먼저 확인한다.
- 선행 기능을 먼저 반영하고 충돌하거나 대체되는 기능은 제거한다.
- 활성 기능은 의존 순서에 따라 등록하며 조작 안내는 마지막에 등록한다.
- 기능 적용을 위해 `src/core/`를 변경하지 않는다. 기존 공개 계약으로 구현할 수 없는 요청만 구조 변경 대상으로 분류한다.
- 기능 제거 후 DOM, CSS, event listener와 timer가 잔존하지 않는지 확인한다.
- 체험자에게는 구현 결과와 새로운 조작법만 안내한다.
